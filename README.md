# 人与 agent 协作规则

本仓库整理人与 agent 协作的基础规则，供其他仓库选择、调整和整合，并保留规则的依据和讨论过程。当前以 Markdown 文件维护通用原则、用词偏好、记录、Git 与代码专题，以及 Serena 使用指南。

## 规则与指南

已确定的规则与配套指南集中在 [rules/](rules/)。通用原则作为入口，记录原则和用词偏好随入口主动完整读取，其余文件按专题组织；新增专题也放入此目录，并更新通用原则中的读取指引。

| 文件 | 内容 |
|---|---|
| [通用协作原则](rules/RULES.md) | 判断与范围、讨论与表达、信息获取与隔离、subagent 的使用、过程与结果。 |
| [用词偏好](rules/WORDING.md) | 可按项目调整、补充的默认用词；初始内容涉及接口与行为的表述。 |
| [记录原则](rules/RECORDS.md) | 内容取舍、表达与原意、文件组织、主动建议记录和原意审查。 |
| [Git 使用约定](rules/GIT.md) | 改动与授权边界、分支和提交的组织、工作目录、集成与提交信息。 |
| [代码相关原则](rules/CODE.md) | 清晰易维护的代码、两种视角与信息隔离、公开约定、复杂度控制、判断与验证，以及工具和记录要求。 |
| [Serena 使用指南](rules/SERENA.md) | 按信息边界定位、读取和修改代码，检查结果及处理信息不足。 |

先完整阅读通用原则，并按其中链接主动完整读取记录原则和用词偏好；其余专题按任务场景读取。向其他仓库整合时，以这些正文和用户确认的采用范围为准。

## 整合到目标仓库

用户要求整合时，agent 按以下流程执行。

1. **阅读规则与项目现状。** 完整阅读 `rules/` 中的规则和配套指南，只读了解待整合项目的结构、规则入口、相关文档和已有约定。若使用 Git，同时检查当前分支和已有改动，保护已有工作。

2. **报告内容和适配方案。** 按主题向用户说明各项规则的具体要求、适用范围、与现有约定的重复或冲突，以及建议放置的位置和合并方式，不只列文件名。由用户选择排除或调整哪些内容；确认采用范围和需要取舍的冲突后，再写入。

3. **适配并写入。** 按确认结果和项目的组织方式进行适配，保留已有有效约定和选定规则的原意，合并重复内容。结合目标项目的语境与使用习惯调整、补充用词偏好。将通用原则及必要的基本要求写入实际使用的规则入口（如 `AGENTS.md`），专题内容放入合适的独立文件。

4. **补齐引用和读取指引。** 在规则入口的记录原则和用词偏好链接处，明确要求读取入口时主动完整读取并遵循。其他专题写清适用场景、读取时机和文件位置，要求 agent 在相关决策或操作前主动阅读，任务出现新场景时补读。入口尽量直接指向专题；使用项目内的相对路径，同步调整文件间的引用，使规则能在项目中独立理解和执行。

5. **整体检查并报告。** 检查采用内容是否遗漏、原有有效约定是否被无意改变、规则是否重复或矛盾，以及适用范围是否清楚、链接、锚点和读取指引是否有效。修正明确问题；需要用户取舍的冲突应说明，不静默选择。最后简要报告修改文件、采用或排除的内容、必要调整、检查结果及尚未解决的问题。

整合内容以 `rules/` 为准，不默认复制原始材料、筛选记录、实验档案或本 README。提交、推送等操作按已有明确授权执行。

## 依据与讨论

已完成 47 份原始材料的筛选与分类：[原始协作要求](collection/REQUIREMENTS.md)包含 14 份约定、目标与偏好，以及散见于产物中的明确诉求；[体现要求的产物](collection/ARTIFACTS.md)包含 33 份讨论、方案、交接和复盘。需要核对依据时，先看要求，再按具体情境查阅产物，并保留原文的确认状态。

[协作原则人工筛选稿](collection/PRINCIPLES.md)保留选出的原文片段及来源，作为规则写作依据，收录内容不直接作为最终规则。

原文保存在 `sources/`，内容和来源相对路径保持不变。[筛选记录](collection/SELECTION.md)、[来源清单](collection/manifest.json)和[六组对比试验](experiments/20261007-181827/REPORT.md)供按需追溯。

[讨论记录索引](notes/README.md)保存组织与整合等议题的讨论脉络。记录中的状态和待定项反映当时情况，当前可用内容以本页链接的规则与指南为准。
