# 人与 agent 协作规则

本仓库整理可整合到其他仓库的人与 agent 协作原则，并保留规则的依据和讨论过程。当前以 Markdown 文件维护通用原则、Git 与代码专题，以及 Serena 使用指南，通过下方 prompt 由 agent 协助整合，按目标仓库的实际情况选择和调整。

README 用于了解本仓库和发起整合。整合后，agent 按目标仓库中的规则入口和专题指引工作。

## 规则与指南

已确定的规则与配套指南集中在 [rules/](rules/)。通用原则作为入口，其他文件按专题组织；新增专题也放入此目录，并更新通用原则中的读取指引。

| 文件 | 内容 |
|---|---|
| [通用协作原则](rules/RULES.md) | 判断与范围、讨论与表达、信息获取与隔离、subagent 的使用、过程与结果。 |
| [Git 使用约定](rules/GIT.md) | 改动与授权边界、分支和提交的组织、工作目录、集成与提交信息。 |
| [代码相关原则](rules/CODE.md) | 设计、实现、审查、测试与过程记录，以及贯穿这些工作的公开抽象和信息边界。 |
| [Serena 使用指南](rules/SERENA.md) | 按信息边界定位、读取和修改代码，检查结果及处理信息不足。 |

先了解通用原则，再按任务场景读取相关专题。向其他仓库整合时，以这些正文和用户确认的采用范围为准。

## 整合到目标仓库

在本仓库中使用下方 prompt，将目标路径占位符替换为实际绝对路径后，交给 agent 执行。

```text
请将本仓库中的协作原则，适配并整合到目标仓库。

规则源仓库：本仓库
目标仓库：<替换为目标仓库的绝对路径>

1. 先只读了解目标仓库的结构、实际使用的规则入口、相关文档和已有约定；若使用 Git，同时检查当前分支和已有改动。再完整阅读本仓库 rules/ 中的规则和配套指南，了解待整合内容。保护目标仓库已有工作。

2. 写入前，按主题向我简要报告本仓库规则与指南包含的具体要求及适用范围，并说明与目标已有约定的重复或冲突、建议放置的位置和合并方式，不要只列文件名。请我决定排除或调整哪些内容；确认采用范围及需要取舍的冲突后再写入，不擅自覆盖冲突约定。

3. 按确认结果适配目标仓库的组织方式，保留已有有效约定，合并重复内容，保留规则原意。将通用原则及不可遗漏的基本要求写入目标实际使用的规则入口（如 AGENTS.md）；专题可放入合适的独立文件，在入口写明适用场景、读取时机和正确位置，明确要求 agent 在相关决策或操作前主动阅读，任务出现新场景时补读。入口尽量直接指向专题，使用目标仓库内正确的相对路径，并同步调整专题之间的必要引用。整合后的规则应能在目标仓库内独立理解和执行，无须再阅读本仓库 README。

4. 整合后整体检查：已确认内容是否有含义遗漏，原有有效约定是否被无意改变，是否仍有重复或冲突，链接和锚点是否有效，适用范围是否清楚，主动阅读指引能否从实际规则入口到达正确文件。修正明确问题；需要用户取舍的实质冲突保留并说明，不静默选择。最后简要报告修改的文件、采用或排除的内容、必要调整、检查结果和本次范围内的未解决项。

只整合有效规则及执行所需的指南，不默认复制原始材料、筛选记录、实验档案或本仓库 README。不要把候选建议或历史讨论直接当作生效规则。保持本仓库不变；提交、推送等操作按已有明确授权执行。
```

## 依据与讨论

已完成 47 份原始材料的筛选与分类：[原始协作要求](collection/REQUIREMENTS.md)包含 14 份约定、目标与偏好，以及散见于产物中的明确诉求；[体现要求的产物](collection/ARTIFACTS.md)包含 33 份讨论、方案、交接和复盘。需要核对依据时，先看要求，再按具体情境查阅产物，并保留原文的确认状态。

[协作原则人工筛选稿](collection/PRINCIPLES.md)保留选出的原文片段及来源，作为规则写作依据，收录内容不直接作为最终规则。

原文保存在 `sources/`，内容和来源相对路径保持不变。[筛选记录](collection/SELECTION.md)、[来源清单](collection/manifest.json)和[六组对比试验](experiments/20261007-181827/REPORT.md)供按需追溯。

[讨论记录索引](notes/README.md)保存组织与整合等议题的讨论脉络。记录中的状态和待定项反映当时情况，当前可用内容以本页链接的规则与指南为准。
