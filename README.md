# 人与 agent 协作原则

本仓库整理人与 agent 协作的原则，供其他项目按需要选择、调整和整合。原则描述协作的意图、判断依据和必要边界，也为具体工作保留自主推理的空间。

## 原则与指南

[通用协作原则](rules/RULES.md)是入口，包含适用于日常工作的基本原则，以及其他专题的读取指引。

- [代码相关原则](rules/CODE.md)：代码设计、抽象与信息隔离、审查、测试和修复。
- [Serena 使用指南](rules/SERENA.md)：借助 Serena 在信息边界内定位、读取和修改代码。
- [记录原则](rules/RECORDS.md)：记录的意义、内容取舍、表达和组织。
- [Git 使用约定](rules/GIT.md)：提交、分支、主线和集成。
- [用词偏好](rules/WORDING.md)：交流与写作中的默认用词，可按项目调整。

入口保留工作中需要持续留意的提醒。专题原则在相关场景出现时读取；任务中出现新的相关场景，也应按需补读。

## 在其他项目中使用

整合到目标项目时，应完整了解本仓库的原则与指南，以及目标项目的结构、规则入口和已有约定。目标项目使用 Git 时，还应了解当前分支和已有改动，保护已有工作。

向用户说明各主题的具体要求与适用范围、和现有约定的重复或冲突，以及建议放置的位置和合并方式。采用范围和需要取舍的冲突由用户确定；已经明确授权或决定的事项不重复确认。

按照目标项目的语境和组织方式适配，保留已有有效约定及选定原则的原意，合并重复内容。通用原则和必要提醒放在实际使用的入口，专题内容放在适合的位置，并说明适用场景和读取时机。

合理使用引用，减少对同一内容的重复维护。例如，一个工具的入口可以引用另一个入口；具体采用何种方式，应根据项目和工具的实际情况决定。引用不意味着所有项目必须使用完全相同、不可调整的规则。

入口尽量直接指向相关专题，使用适合目标项目的路径，并使整合后的规则能够在项目中独立理解和执行。完成后检查内容是否遗漏、原有约定是否被无意改变、规则是否重复或矛盾，以及适用范围、链接和读取指引是否清楚有效。需要用户取舍的问题应明确说明，最后报告实际采用和调整的内容。

整合原则不等于默认复制本仓库的原始材料、筛选记录、实验档案或使用说明。
