# 记录原则草案

本稿保留定稿前的讨论版本，现行规则见[记录原则](../../rules/RECORDS.md)。

## 适用场景

记录场景大致分为三类：

- **理解与探索**：想法讨论、知识学习、资料调研、复盘与经验总结。
- **设计与决策**：方案设计、比较、选择与取舍。
- **实践与验证**：工作实施、问题排查、实验与测试。

具体活动可以跨类，不为每类记录规定固定结构。

## 内容取舍

以内容对理解和脉络的作用作为取舍依据。

保留理解问题及其演变所需的内容，使读者能够了解初始问题、想法与讨论如何发展、选择及结果如何形成。影响理解的依据、分歧、失败尝试和转折应予保留。

关键内容表达充分，重复且不增加信息的表达可以合并，无关的操作细节可以省略。避免让大量次要细节淹没要点。

已有可靠资料按需引用或提供定位，减少重复维护无关、易过时的状态。若某个当时状态影响了判断，应保留相关事实及其影响。

## 表达与原意

表达清晰、简洁、易于阅读和理解，结构和详略随内容安排。

整理、合并或压缩时保持原意，不补出未发生的过程。明确区分用户与 agent 的表述，保留必要的不确定性，不将猜想、候选或未决事项写成已确认结论。

## 文件组织

记录文件应按内容的主题、用途和相互关系组织，结合仓库现有结构选择合适的存放位置。目录和文件命名应清楚反映内容，相关记录按需建立引用，方便检索和查看。

## 主动建议记录

agent 应主动留意当前的讨论和工作进展，在已有内容足以形成一份有意义的记录时，主动建议记录。

## 审查

审查所用的原始材料，优先取自相关的本地 session 记录文件，按需提取原始对话并保留出处。来源不可用或不完整时，说明限制并补充其他可核实材料。摘要或整理稿不能替代可获取的原文。

适当使用 subagent 独立审查，重点比对根据原始材料和整理结果分别形成的理解，检查影响理解的遗漏、含义变化和无依据的补充。

审查意见应回到材料核实，并说明差异及其影响。合理压缩产生的详略差异可以接受；原始材料阅读者的理解也需要核验。

## 尚未定型的部分

具体审查配置仍可调整。已提出的方案是“两位独立阅读者＋一位比对审查者”，具体安排由 agent 根据材料规模和重要性决定，不将三角色方式规定为每次必做的流程。
