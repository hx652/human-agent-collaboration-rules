# 记录适用场景的讨论

用户认为记录适用的场景已大致明确。以下三类作为当前讨论基础，用于理解场景，不预设每类记录的固定结构。

## 用户已提出的范围

用户希望主要按记录内容分类，举出了与 agent 讨论想法、学习知识或概念、讨论代码设计等例子。长期保存 Session 中的理解与进展是记录的重要作用；用户后来强调，跨 Session 延续和多个 agent 协作是形成记录后的好处。

## 讨论中的调整

agent 最初提出想法探索、知识学习、调研与比较、设计与决策、实践与问题解决、复盘与经验六类，并同时列出各类值得保留的内容，还提出选择一类继续讨论内容取舍。

用户提醒：“稍等一下我们先明确场景”。agent 据此将讨论收回到场景本身，暂不展开记录内容与写法。

## 最初列出的具体场景

1. 想法讨论与探索。
2. 知识、概念的学习。
3. 资料调研与比较。
4. 方案设计与选择。
5. 工作实施与推进。
6. 问题排查与解决。
7. 实验、测试与验证。
8. 复盘与经验总结。

相较于用户最初的例子，agent 补充了调研、实施、排查、验证与复盘，并将代码设计暂扩展为更一般的方案设计，在这一阶段作为候选提出。

## 大类划分的讨论

用户希望在具体场景之上再归纳几个大类，并认为想法讨论与探索、知识学习很相近。agent 据此提出三类：理解与探索、设计与决策、实践与验证。

关于复盘与经验总结，agent 最初建议将其看作贯穿各类的回顾方式。用户认为它与想法或学习接近，无须单列，同时明确这只是当前想法。agent 赞同将其归入理解与探索：复盘同样是在经历的基础上形成认识、提炼经验和修正理解。

经过上述归并，形成以下三类。用户随后表示，使用场景已经大致明确。

| 大类 | 包含的具体场景 | 活动的主要目的 |
|---|---|---|
| 理解与探索 | 想法讨论、知识学习、资料调研、复盘与经验总结 | 理解问题，形成和修正认识，探索可能性。 |
| 设计与决策 | 方案设计、方案比较、选择与取舍 | 确定要做什么、怎样做。 |
| 实践与验证 | 工作实施、问题排查、实验与测试 | 通过实际行动解决问题、检验想法。 |

具体活动可以跨类，例如代码设计可能经历探索、决策和验证，不要求每段工作只归入一类。

## 记录带来的好处

agent 曾将跨 Session 延续和多个 agent 协作称为贯穿各类场景的使用方式。用户澄清，它们是形成记录后的好处。后续按这一含义理解，不将其列为记录的内容类别。

## 场景分类与表达方式

用户认为，无法为每类场景使用一个确定性的记录结构，这可能限制表达能力；同时提出，是否还需要讨论每类具体记录什么。

agent 的当前意见是：可以讨论缺少什么会让读者看不懂这段过程，以及哪些细节没有实际帮助，再据此取舍和组织。场景分类帮助判断重点，结构随本次内容安排；不必逐类规定栏目、顺序或必填项，也不补齐实际没有发生的环节。

例如，学习记录中一个澄清误解的例子可能不可省略，设计记录中某次取舍的理由可能尤为重要。这些只是帮助判断内容价值的例子，不是各类记录的必备清单。

用户随后认可此前的判断，讨论进入[内容取舍原则](content-selection.md)的进一步明确。
