# 记录内容取舍的讨论

用户认可此前提出的判断：缺少什么会使脉络断裂，哪些细节对理解没有帮助。场景已大致明确，现在据此进一步讨论内容取舍；不为各类记录预设固定结构。

## agent 提出的原则展开

以下四项是 agent 对上述判断的展开建议。用户随后表示“好的”，并提出补充 subagent 审查；具体规则表述尚未定稿。

1. **保留理解脉络所需的内容。** 让后来的读者能够理解问题从何而来、认识或选择怎样形成、为何发生变化。影响理解的讨论、分歧、失败尝试和转折都可能值得保留，不因它们没有进入最终结论就删除。

2. **详略与内容的重要性相匹配。** 关键依据、例子和细节应表达充分；重复且不增加信息的表达可以合并，无关的操作细节可以省略。简洁通过去除重复与无关内容实现，同时保留理解关键内容所需的具体性。

3. **合理利用已有资料，减少重复维护。** 对能从可靠来源直接核实的内容，按需要提供引用或定位，避免在正文中重复维护无关、易过时的状态。若某个当时状态本身影响了判断，就保留相关事实及其影响。

4. **整理时保持原意与确认状态。** 合并或压缩不应改变原意、补出未发生的过程，或把猜想、候选和未决事项写成已确认结论。用户与 agent 的不同意见及其归属，在影响理解时应保留。

这些是内容取舍的判断依据。具体记录采用什么结构、顺序和表达方式，仍由内容决定。

## 用户补充的审查方向

合适地使用 subagent 审查，关键是比对根据整理后结果形成的理解与根据原始材料形成的理解。用户将具体方式交由 agent 安排，并要求先说明方式。

agent 提出的[理解比对审查方案](review-approach.md)采用两位独立阅读者和一位比对审查者。方案先作说明，后按用户要求，以本地 session 为主要来源完成了[首轮草案审查](intent-review/README.md)。

## 用户补充的记录时机

agent 应主动留意当前的讨论和工作进展，在已有内容足以形成一份有意义的记录时，主动向用户建议记录。

agent 当前建议：本次讨论已覆盖记录的目的、场景、内容取舍、审查方式和记录时机，适合汇成一版整体草案，保留其中尚未定稿的内容。
