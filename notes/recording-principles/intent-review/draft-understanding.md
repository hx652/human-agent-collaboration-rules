# 草案独立理解

我理解这份稿件是在提出通用的记录原则：通过取舍、组织和压缩，让读者清楚理解问题及其发展过程，同时保存原意与未确定状态；它不是要求逐字收录全部讨论（D15—D27）。

**原则要求**

- 内容是否保留，取决于它对理解问题和脉络的作用。初始问题、讨论发展、选择与结果的形成应能看明白；影响理解的依据、分歧、失败尝试和转折需要保留。重复内容可以合并，无关操作细节可以省略，但关键内容应表达充分（D15—D19）。
- 可靠的现成资料可以引用或定位，以减少重复维护；如果某个历史状态影响了当时判断，仍需记录该事实及影响（D21）。
- 表达要清楚、简洁，结构与详略由内容决定。压缩不能改变原意、编出过程或把猜想和未决事项写成确定结论；用户与 agent 的表述应有区分（D25—D27）。
- 文件按主题、用途和关系组织，并适配仓库结构，命名和引用应方便查找（D31）。
- agent 应在内容足以形成有意义的记录时主动提出记录建议；这里表达的是“建议”，没有直接规定随后自动写入（D35）。
- 可适当借助 subagent 独立审查，将分别阅读原始材料和整理稿得到的理解进行比对。意见还要返回材料核实，允许合理压缩造成的详略差异，也不能直接把原始材料阅读者的理解当作裁定依据（D39—D41）。

**背景、工作过程与状态**

三类场景说明原则可能适用的活动范围，分类可以交叉，不是要求每类采用固定模板（D5—D11）。全文未单独列出只针对本次整理工作的步骤或交付要求；审查段落的措辞仍像通用原则（D39—D41）。

稿件整体仍标为“草案”（D1）。各条被写成原则性要求，但文中没有交代是谁提出、哪些已经认可，也没有展示修正前后的变化，不能据此还原提议、认可和修正的过程。

明确标为未定型的是具体审查配置：稿件称已经提出“两位独立阅读者＋一位比对审查者”，尚未试用，仍可调整；配置由 agent 根据材料规模和重要性决定，三角色并非每次必做（D43—D45）。这项具体提议不等于已经验证有效。

**含糊之处**

“可靠资料”“有意义的记录”和“适当使用”的判断标准未展开，因此引用什么、何时建议记录、何时启用独立审查，仍需结合实际材料判断（D21、D35、D39、D45）。现有文字不足以判断这些留白是有意保留弹性，还是尚待补充。
