# Subagent 上下文调研安排

日期：2026-10-12

依据：[用户观点与调研要求](../2026-10-12-subagent-principles.md)。目标是了解当前上下文划分、工程实践及自主委派的证据，为讨论原则提供材料。

## 分工

三位调研 subagent 均按用户要求配置为 `gpt-6.1-sol`，推理强度 `max`；调用已成功创建。

| 调研者 | 职责 | 主要交付 |
|---|---|---|
| context_mechanisms | 官方机制与上下文设计 | 上下文来源、继承和隔离、结果回传、自主委派机制及产品差异 |
| context_practice | 工程实践与社区讨论 | 研究和开发等任务中的实际做法、成功条件、失败经验与成本 |
| context_evidence | 实验证据与自主决策 | 多视角和动态委派的效果，计算资源等混杂因素，以及结论的适用边界 |
| 主 agent | 综合与关键来源复核 | 对照各项发现与用户观点，区分来源结论、推断和待讨论选择 |

## 信息边界与协作

三位均使用 `fork_turns=none`，不继承主会话的对话历史；仍受平台和工具指令约束。委派内容提供中立研究问题和证据要求，不提供用户观点原文、仓库规则或其他调研者的结论。要求不读取用户记忆、仓库、主会话历史和其他调研者产物，不互相交流，不再创建下级 subagent。

每位仅写自己的临时调研文件，主 agent 统一整理到本分支，避免并行修改同一文件。主 agent 保留完整讨论背景，负责将独立发现与用户观点对照。上述边界是本次任务指令，并不构成操作系统或工具权限上的强制隔离；也不意味着三个同模型上下文的错误在统计上独立。

## 证据要求

使用实际打开核实的一手来源，包括官方文档、项目作者复盘、原始社区讨论与研究论文。区分功能说明、建议、项目自述和有对照的实验证据。记录来源链接、日期或日期缺失、关键定位及局限。

量化收益应核对基线、模型、token 或计算量、任务与指标；不能将更多计算或并行搜索带来的收益直接归因于上下文隔离。主动收集适用限制和失败案例，不以赞同或反对用户观点为预设结论。

本轮交付为调研和讨论材料，不自动成为正式原则。未开展本地对照实验。

## 本轮完成情况

三位均已提交独立调研结果。主 agent 阅读三份报告，并补充核对关键官方页面、2026 年实践更新、具体 issue 评论及主要论文版本；综合结果保存在[调研报告](README.md)，采用来源与核验说明保存在[来源索引](sources.md)。

结果保留官方能力、工程自述、用户报告与研究实验的差别，没有按三位调研者的多数意见判定事实。调研完成时尚未修改正式规则或执行本地提交、合并、推送；之后的交付审查与提交状态见[交接说明](../subagent-handoff.md)。
