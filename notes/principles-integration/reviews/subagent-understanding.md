## Subagent 原则

正式入口要求 agent 积极识别适合独立分工、独立判断或上下文隔离的工作，依任务自主安排和调整协作；没有要求所有任务都必须委派，也没有规定固定数量或统一配置。

委派时需按职责和信息需要配置上下文，提供任务必需的背景、知识、依据、引导、目标、约束和共同约定，减少无关信息，同时保留 subagent 自主判断、探索和调整的空间。引导详略取决于任务需要，不等同于一律不给背景或一律提供主会话全部历史。

新建 subagent 可按需要选择主会话背景继承范围；复用已有 subagent 时，应检查历史是否相关、是否影响独立判断。做法受当前工具支持限制。模型和推理强度的选择同样以工具可选为前提，先满足任务要求，再结合难度、成本和时间。

向用户的简要说明包含职责分配、模型、推理强度和上下文构成。不同上下文和探索方向用于取得互补视角；主 agent 负责协调、整合、判断分歧和共识及必要核验。传递信息时保留关键依据和不确定性，不能把 subagent 的结论直接当作无须核验的事实。

## 职责与信息边界

通用的信息隔离要求覆盖上下文继承、消息转述、文件和工具输出等途径；安排上下文的自主权没有给予放宽已约定信息权限的权力。按需阅读也受完整阅读的明确要求约束。

代码专题进一步限定信息范围：设计与架构审查依据当前层级的公开职责、能力和约束；实现者可以读负责范围内实现，但不得获取依赖内部实现；需要隔离的实现由不同上下文处理。测试编写者不得持有或直接、间接取得被测实现信息。主 agent 可以在受限架构审查形成并保存独立判断后对照全局参考，但受限审查上下文提前接触参考会破坏独立性。

因此一般的积极协作、自主背景配置与探索，应服从每项任务已有的职责和信息边界；复用已有 agent 的历史检查尤其关系到这些专门限制。

## 与其他规则的关系

- Git 约定优先由 subagent 制定提交方案，同时保留提交、集成、推送和共享历史修改各自的授权边界。提出方案没有取得执行授权；并行修改按需隔离工作目录和产物，不强制每个小任务使用 worktree 或 PR。
- 记录原则在整理双方交流时默认采用原意审查，使用 subagent 独立形成和比对理解，可按材料规模选择具体配置。原始材料及审查者的理解都要回查，合理压缩可接受。记录内容、原始材料与当前正式规则具有不同地位。
- Serena 指南把信息范围落实到查询和诊断工具；工具参数不是权限隔离，不能先读越界材料再声称忽略。工具不可用或查询不足不产生自行放宽边界的权利。
- 通用“主动建议记录”和记录专题的同项要求存在内容重复，但入口提示与专题细化一致；现阶段未看到因重复而形成的矛盾。各专题是在通用协作原则上细化场景，未把积极委派扩展为新的任务目标或额外授权。

README 将 `rules/` 定义为当前规则和指南的正文来源，目标仓库整合须按用户确认的采用范围进行；讨论索引中的草稿、交接和历史状态供追溯，不直接决定当前规则。基于正式文本，本阶段未见 Subagent 部分与组合规则的实质冲突；来源是否支持这些措辞及原有要求是否保留，留到第二阶段检查。
