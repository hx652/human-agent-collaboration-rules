# 长期探索与过程记录

通过讨论、与 Agent 协作实践和持续记录，推进长期探索，
并保留思考与行动的演变过程，让后续工作和未来回顾都有据可循。

科研是第一块实践场景，工作方式以后可以用于其他领域。
记录本身也是目标，不只为下一次 session 提供上下文。

## 阅读入口

- [研究概览](overview.md)：方向、背景和原则。
- [当前状态](state.md)：进展、问题和下一步。
- [项目索引](projects/README.md)：具体项目与代码仓库入口。
- [过程记录](journal/)：讨论、尝试、决策和复盘。
- [随手记录](inbox/)：尚未成体系的想法。
- [实验记录](experiments/)：实验问题、设置、结果和解释。
- [文献记录](references/)：文献入口与阅读笔记。
- [配套资源](assets/README.md)：插图、附件与生成源文件的存放和引用。
- [协作约定](AGENTS.md)：Agent 的读取与记录更新方式。

## 使用循环

1. 开始 session 时，明确要求 Agent 读取协作约定、概览、
   当前状态和项目索引，再按任务查阅详细记录。
2. 讨论或实践，在重要节点整理记录。
3. Agent 提出拟修改文件及具体候选内容。
4. 用户审阅、修改并确认后，Agent 写入。
5. 检查 Git 差异，提交有意义的记录节点。

不要求记录每轮对话，但要保留重要尝试、选择理由和理解变化。
如果 session 无法访问文件，需要提供相关材料，不能假定已同步。

## 维护

overview.md 保存当前整体理解，state.md 保持简短。
详细过程通过链接查阅，项目实现说明优先引用代码仓库。
结论变化时更新当前状态，同时记录改变的原因，保留原始探索。
Inbox 按需回看，不要求清空。
旧材料按需逐步迁入，并注明来源。
原始数据集、密钥和大体积实验产物不放入本仓库。
供笔记阅读的小型附件、自制插图及其维护源文件放入 assets/，使用库内相对链接；
资源来源、生成方式和限制按组说明。可再生成的导出副本按需生成。

跨设备同步是必要的后续能力，计划配置私有 Git 远程，
第一版暂不配置。设备专属路径写入不受 Git 管理的
local-paths.md。

当某块内容需要频繁独立阅读、更新或引用时再拆分，
不只根据字数提前设计。
