## 从读取结果谈起

用户提出先明确读取向后续步骤交付哪些抽象。讨论选择“完整、可解释的领域对象，计算能力随后建立”：解析后不再依赖 YAML 的字段布局，但不要求同时初始化 IK、碰撞或渲染后端。

用户提出 robot、scene、generation，以及由 scene 和依赖它的 generation 构成 input 的方向。输入 folder 是否需要表示暂未决定；希望名义场景与输出场景复用基础表示，避免重复设计。

## 机器人：共享模型与具体实例

用户将机器人模型理解为“URDF＋配置”的模板。配置用明确字段保存；URDF 解析为 joint、link 等表示，并核对引用和资源，而不只是记录原文件。父子 link、mimic、规划关节和 TCP 等引用在读取时关联到对象或稳定索引，具体容器未定。

对于 URDF 与配置中的重复信息，用户确定配置覆盖 URDF，未提供的沿用 URDF 默认值。非规划关节仍属于状态，但首版继续使用公共配置中的固定夹爪值，不增加逐问题变化能力。

Scene 中的机器人则是引用共享模型的实例，拥有安装位姿和自身状态。名义场景中未定的是规划关节状态，具体场景中保存实际初始状态；不能用零值代替“未指定”。实例 pose 表示 root_link 在参考系中的位姿，参考系为 world 并不矛盾。

局部方案预览：

```text
RobotModel
  links、joints、根 link、名称查找关系
  公共配置：规划关节及顺序、TCP、有效限位、固定关节值、命名配置、自碰撞排除
Link
  名称、visual 几何条目、collision 几何条目
Joint
  名称、类型、父子 Link、origin Pose、运动轴、URDF 限位、mimic 关系
```

公共配置与 URDF 整合后提供有效值，原值可保留供追溯。模型不保存实例安装位姿或可变规划关节状态，也不包含计算后端。碰撞排除可用 link 对集合或矩阵，暂不决定容器。

## Mesh：从提前解析转向按需加载

agent 起初倾向读取时解析 mesh；用户指出可能不必要且占内存，倾向先保存资源引用。对当前样例的 18 个 STL 实测：21,290 个三角面，以 float64 保存未合并顶点约占 1.46 MiB；不含碰撞加速结构和渲染数据，不能推广为所有模型的开销。

讨论转向轻量 MeshResource：保存已解析的路径和格式，核对文件引用，几何内容按需加载。用户要求路径采用规范的路径 class；相对路径用于解析关联，系统内部使用规范化绝对路径对象。格式可由扩展名推断，内容能否解析及缓存策略之后再考虑。

用户质疑额外的 MeshGeometry 层，目前去掉：几何条目直接引用 MeshResource，并保存本次使用的局部 pose 和缩放。visual 与 collision 保留独立用途，必要时可引用同一资源。

局部方案：`MeshResource = 规范化绝对路径对象＋格式`。读取时以引用文件所在目录解析相对路径，检查文件存在且可读；不加载顶点、三角面，也不增加加载状态、缓存或资源管理框架。读取结果仍依赖磁盘上的 mesh 文件。

## Pose、Frame 与场景复用

用户倾向建立 Pose、Frame 抽象，便于理解和扰动。讨论区分：Pose 保存平移、旋转数值；显式 Frame 保存身份、父 frame 和相对 pose。物体、安装位置、目标引用 frame；普通几何偏移仍可只用 Pose，不为每个偏移建立命名 frame，也不重复保存同一位姿。

机器人 link 的相对变换还依赖关节状态，暂不另建一份重复的可变 frame 树；与场景 frame 的衔接继续讨论。名义与具体场景复用基础结构，但采样生成独立状态，不修改名义值；模型和固定几何可以共享。

局部方案：`Pose = 平移＋旋转`，不保存父 frame 或采样分布；`Frame = 标识＋父 Frame 引用＋相对 Pose`，world 无父 frame。检查引用存在且无环，世界 pose 沿关系计算，暂不缓存。generation 采样增量，再按已确认的局部坐标约定作用于名义 Pose，得到新值。

## Compound 与基本形状

用户所说的 compound 内部结构就是几何条目列表。列表及各条目的局部 pose 应保留，供碰撞检测和可视化建立各自表示；整体扰动只改变物体 pose，内部关系不变。

随后确认为 Box、Sphere、Cylinder 等基本形状建立明确类型，统一完整边长、半径、中心和轴向等含义，不让后续反复解释参数。形状与使用位姿分开，具体方法及后端转换用到时再讨论。

局部方案：

```text
几何条目：形状参数或 MeshResource 引用＋局部 Pose＋mesh 缩放（适用时）
Box：三个完整边长，中心为原点，边沿局部 x/y/z
Sphere：半径，球心为原点
Cylinder：半径、高度，中心为原点，轴线沿局部 z
```

基本形状参数应有限且大于零；类型不绑定碰撞库或渲染库。机器人 Link 与环境 Object 可复用这些基础表示。

### 补充：几何局部位姿与缩放（2026-09-29）

`Geometry.local_pose` 表示几何体自身坐标系在所属参考系中的位姿；所属参考系通常为物体 frame 或机器人 link frame。几何坐标系可以隐式定义，不必创建独立 Frame：基本形状沿用上面的原点与轴向约定，mesh 沿用资源自身坐标系，不根据顶点重新推导中心或轴向。

采用列向量，local_pose 的旋转和平移记为 R、t：`p_parent = R @ p_geometry + t`。mesh 有缩放时，先在自身坐标系中缩放，再应用 local_pose，即 `p_parent = R @ (S @ p_mesh) + t`，其中 S 为各轴缩放构成的对角矩阵。缩放不会改变 local_pose 的平移量。


## Scene 的局部方案

围绕机器人实例、compound 和 frame 的讨论，agent 给出的场景预览为：

```text
Scene：世界 Frame、Frame 集合、机器人实例、环境物体、场景规则
RobotInstance：实例 ID、RobotModel 引用、安装 Frame、规划关节状态（未指定／已指定）
Object（当前 compound）：实例 ID、自身 Frame、几何条目列表
```

安装 Frame 与 root_link 重合；Object 的位姿只由自身 Frame 保存。访问目标是 Scene 中的显式 Frame，generation 引用它来定义扰动与访问序列。名义与具体场景使用相同基础表示，分别保存名义 pose 与采样 pose；具体场景还具有确定的初始规划关节状态。

完整输出问题除 Scene 外还需任务内容，如访问序列、辅助 IK、容差与完成条件，不全部塞入 Scene。有关节环境物体、机器人 link frame 的衔接仍待展开。

## 场景规则的澄清

environment_motion 为 static 表示任务执行期间环境不动，不禁止生成时扰动。allowed_mount_contacts 表达实例层面的安装接触关系；当前检查脚本忽略指定 robot link 与指定 object 的碰撞，并非忽略整个机械臂。用户认为暂不必细化接触区域。

agent 建议输出保留这些规则的含义，当前继续显式表达；具体输出组织未进一步定稿。generation 的内部表示、输入目录对象和更完整的场景接口仍待讨论。
