# 记录原则

## 记录的意义

过程与结果都有价值。讨论、设计、学习和实践中遇到的问题、形成的想法，以及认识如何变化，都是值得保留的内容。

设计体现的是在具体情境下作出的选择。记录当时的问题、考虑和依据，有助于后来理解这些选择，也为重新思考提供背景。学习与探索即使尚未形成结论，也可能产生值得保留的认识和问题。

记录适用于想法讨论、知识学习、资料调研、设计决策、实施验证、问题排查和经验总结等场景。记录方式随内容和用途安排。

## 重点与脉络

围绕记录希望表达的主要问题或主题组织内容，使读者能够把握整体意思，理解讨论和工作是怎样展开的。

根据实际内容，保留初始问题、相关背景、想法与判断、遇到的困难、尝试与反馈、选择及其依据，以及重要的转折和认识变化。保留足够具体的内容，让过程中的联系和变化可以被理解。

记录可以用自然连贯的叙述，也可以围绕相互关联的线索组织；详略和结构以内容需要为准。

## 内容取舍

以内容对理解主要问题及其过程的价值为依据，决定保留什么、展开到什么程度。关键内容表达充分；细节围绕其对理解、判断或学习的作用取舍，使重要信息清楚可见。

agent 应主动识别和提炼讨论、学习、实践和审查中的有价值线索，包括自己发现的问题、形成的理解，以及对原有看法的修正。与最终结果没有直接关系、但有助于理解或学习的发现，也可以保留。

代码和已有可靠资料能够直接说明的内容，可根据理解需要简要交代或提供定位。原意、选择理由、认识变化和过程中的发现，应得到足够表达；当时的状态影响判断时，保留相关事实及其影响。

## 表达与原意

记录应当自足、清晰、易读，使读者通过记录本身理解主要内容和必要脉络。相关文档、代码或原始资料可按需引用，供进一步阅读和核实。

整理时忠实呈现原始脉络及其含义，让相关背景、想法的发展、选择和认识变化之间的关系清楚可见。是否保留原话，根据内容和理解需要判断；可以采用引述、转述或概括等方式表达。

清楚区分用户与 agent 的观点，以及事实、推断、建议和已确认的选择。保留有意义的不确定性、分歧和未决事项。

## 文件组织

根据内容的主题、用途和相互关系，结合项目现有结构安排记录。文件和目录名称应便于识别，相关材料按需建立引用，方便检索和阅读。

## 主动留意记录

agent 应持续留意讨论和工作进展，在已有内容足以形成有意义的记录时，主动向用户建议记录。有明确记录要求时，按要求执行。
