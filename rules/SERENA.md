# Serena 使用指南

## 开始使用

首次使用时，读取 `initial_instructions`。通过 `get_current_config` 核对当前项目；项目不匹配时，使用 `activate_project` 指定正确的项目路径。

查询前，明确需要什么信息，以及允许读取哪些文件、符号和实现。项目已激活，不代表其中所有内容都在本次允许范围内。

## 定位与读取

| 需要的信息 | 使用方式 |
|---|---|
| 文件中的符号结构 | 使用 `get_symbols_overview`，限定文件并按需设置 `depth`。概览可能包含内部符号，仅在这些信息属于允许范围时使用。 |
| 指定符号的位置和信息 | 使用 `find_symbol`，通过 `relative_path` 和 `name_path_pattern` 限定文件或目录及符号，避免无范围的模糊查询。 |
| 公开签名和文档 | 设置 `include_body=false`；确认签名和文档属于允许信息后，再设置 `include_info=true`。 |
| 允许读取的实现 | 对指定符号设置 `include_body=true`。不要为查看一个方法而读取整个类的正文。 |
| 调用所指向的声明或定义 | 使用 `find_declaration`，默认不返回正文。定位到某个符号，不代表它属于允许读取的公开接口。 |
| 调用和使用位置 | 使用 `find_referencing_symbols`。结果包含引用附近的代码，必须先确认返回范围符合信息边界。 |

`depth` 控制是否展开子符号，不负责过滤私有成员。`include_info` 不会自动应用于子符号；需要某个方法的说明时，应单独查询该方法。

引用查询中的 `relative_path` 指被查询符号所在的文件，不限制引用结果来自哪些文件。受限上下文无法确认结果是否合规时，不直接调用，改用明确允许的调用场景或交接材料。

签名、文档和语言服务提供的信息，不自动等于完整的行为契约。公开材料没有说明的行为，不应自行补作约定。

## 修改与检查

整段替换已获准修改的符号时，可使用 `replace_symbol_body`；在符号前后插入内容，可使用 `insert_before_symbol` 或 `insert_after_symbol`。

替换前，先读取允许范围内的完整定义。Serena 所称的符号正文可能包含签名及文档注释，不能将它误当成只有函数内部的语句。

需要诊断信息时，使用 `get_diagnostics_for_file`，按需限定文件和行范围。诊断信息同样受信息边界约束，不因它来自工具就默认可以读取。使用行范围参数时，注意 Serena 行号从 0 开始。

## 信息不足或工具不可用时

Serena 不可用时，先暂停相关代码操作并向用户说明情况，由用户决定如何处理；不得自行放宽信息隔离要求。

Serena 可用但查询不到所需信息时，先检查项目、语言服务和查询范围。找不到信息，不等于设计缺少该信息。

工具无法控制返回范围时，读取明确允许的接口或契约材料；仍缺少必要信息时，说明具体缺口，不改用整份源码、广泛搜索或其他渠道绕过隔离。

查询参数控制返回内容，不构成强制的访问权限隔离。不能先读取受限内容，再声称忽略它。
