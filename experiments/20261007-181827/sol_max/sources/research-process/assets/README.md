## 存放与引用

每组需要长期维护的资源使用一个稳定的主题目录。README 简短说明用途、来源、关联笔记、修改入口、生成方式及重要限制，不要求每张零散截图都单独建立说明。

笔记用标准 Markdown 相对路径引用。例如从 inbox/ 的笔记引用插图：

```markdown
![公共边上的对应点](../assets/cube-complex/03-corresponding-boundaries.svg)
```

移动或改名后检查引用。不要在长期笔记中仅链接临时目录或会话输出位置。

Obsidian 的新附件默认位置已设置为 assets/；该设置只决定存放入口，不自动按主题整理，也不会迁移历史附件。

## 版本与导出

小型维护资源可随笔记提交普通 Git。普通修正沿用名称，提交后才有 Git 历史；需要并排比较的方案另行命名。

绘图脚本是修改入口，SVG 是本组笔记的展示格式。PNG、总览、ZIP 等派生副本按需生成，放在相应资源组的 exports/ 中，该目录不进入 Git。不可再生成或需要独立保留的原始 PNG 等附件不受此规则排除。

## 外部资源

原始数据集、长视频、模型权重及大批日志留在项目或数据目录；笔记记录名称、版本或运行编号与位置。设备专属路径写入不受 Git 管理的 local-paths.md。外部文件的同步和备份需要另行安排，不能用一条链接替代。

论文 PDF 是否入库按用途、体积和维护需求决定；本次不安装 Zotero、Git LFS 或 DVC，也不配置远程同步。
