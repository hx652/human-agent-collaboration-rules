# 实现单元与代码职责的区别

日期：2026-09-29

状态：对实现单元划分建议的补充说明；不在此决定将表示与读取合并还是拆分为独立任务。

## 问题与澄清

此前建议将机器人、场景等“表示与读取”放在同一个实现单元，但保持代码职责分开。用户询问这一表述的含义。

同一个实现单元指同一项任务一起交付，不意味着写进同一个 class，也不要求放在同一文件。例如机器人单元可以同时交付：

```python
class RobotModel:
    # 保存 links、joints、公共配置等模型表示
    ...

def read_robot_model(config_path, resources) -> RobotModel:
    # 解释配置与 URDF，构造对象并建立关联
    ...
```

其验收目标是“可以从输入文件得到正确的 RobotModel”。RobotModel 负责表示和使用模型数据，读取逻辑负责文件解释、对象构造及关联建立；示意名称和签名不是已定稿接口。

## 对契约隔离实验的影响

把二者作为一个实现任务，检验的是这个单元与其他单元之间的契约边界，不是在检验“机器人读取逻辑能否仅凭 RobotModel 的公开契约独立实现”。

若也希望检验后者，应将表示与读取拆为两个实现任务：先明确 RobotModel 的公开契约，再让读取实现任务仅依据契约使用它，不读取模型内部实现。仅将代码分成两个 class 或文件，并不会自动形成这种阅读隔离。

因此，实现任务的粒度需要与希望检验的边界相匹配；代码职责分离与任务范围分离是两个相关但不同的选择。
