本轮来源仅为 `/home/fainic/data/research-process` 和 `/home/fainic/data/multiarm-problem-gen` 的当前工作区。输出仅写入本组 `sol_xhigh` worktree，全部文件操作明确使用该目录为执行工作目录；写入通过已授权范围内的工具提权完成。没有创建子 agent、提交、合并、推送、运行来源脚本或执行原文中的任务。

## 实际方法与覆盖

使用目录清单、`rg --files --hidden --no-ignore`、Markdown 标题/状态读取、针对 agent、用户、授权、确认、复盘、契约、阅读边界等词的内容检索，以及重点上下文读取判断相关性。目录清单包含忽略/未跟踪文件；统计与可核验路径见 initial-inventory.json。原文件内容读取与输出复制均按字节处理，未转码、换行、摘录或改写副本。

Git 只用于 status 和 ls-files 判断当前文件状态，每次显式设置 GIT_OPTIONAL_LOCKS=0，未请求历史版本、分支差异或对象内容。原始状态输出保存在各仓库 *-status-initial.txt 和 *-ignored-initial.txt；最终输出另存。未进入外部网站或追读源材料所引用的外部仓库/设备路径。

Markdown 共 79 份，逐文件看标题、状态和相关段落；核心约定、调研和实施/复盘全文读取，其余按内容检索读取关键段落。纯业务接口与格式、算法文献、第三方模型说明等经过筛查后排除；完整排除清单解释每份 Markdown 及其他文件的理由。非 Markdown 的业务源码、测试、配置和 HTML 作文本关键词筛查；匹配 userAgent 等技术字符串不视为协作内容。MotionBenchMaker.pdf、网格、教学图、导出图、wheel 和 pickle 缓存没有全面内容解析；仅依据文件类型、当前说明材料并计算字节摘要。

## 必须披露的检索偏差

1. 首轮 `rg --files` 的排除模式使用 `!.git/**`，在传入绝对根路径时未正确排除 .git。该次清单输出了 .git 对象和引用的路径名称。这违反了不进入 .git 对象/历史区域的检索边界；没有打开对象内容、没有请求或采用历史版本，也没有将这些路径纳入来源清单或资料判断。发现后停止该枚举方式，改用 `!.git` 与 `!**/.git/**` 的双重排除；可靠工作区清单为 268 个文件。
2. 一次研究仓库 Markdown 标题补充枚举使用 Path.rglob 后按路径过滤 .git，会遍历其目录名称，过滤发生在遍历之后；该次未返回 .git 中的文档正文。后续来源枚举全部使用 os.walk 在进入目录前剪枝 .git，并不跟随链接。两个偏差已及时向主调度者报告。
3. 部分批量读取的工具输出被截断；涉及决定记录尾部、主要约定及纳入依据时使用限定文件/章节重新读取。不能把被截断的输出当成已经完整可见。
4. 宿主没有 `python` 命令，首个只读清单脚本未执行；改用已有的 `python3 -B`。没有为此安装依赖或写入来源缓存。

这些事实如实保留，不能声称本轮从未遍历 .git 路径。之后没有进一步展开其内容，也未据此补充历史材料。

## 校验的意义与限制

初始清单是在上述检索纠正后建立的所有工作区文件 SHA-256、大小、权限位和修改时间快照。最终再次枚举并对比它们，用于检测此区间内的内容/元信息变化；不是对任务开始前历史状态的证明，也不能排除外部并发写入后又恢复的情况。来源文件未被本组写入或改变权限；Git 只读查询避免可选锁和索引刷新。未比较 .git 对象/元数据文件内容。

每份副本与当前原文做实际字节比较和 SHA-256 比较；索引相对路径和关键章节标题/行号另外验证。原文自身的所有外链、相对引用及数学/技术主张不在本轮完整验证范围，原文未为使链接自足而改写。历史测试数与边界自述只按原文状态索引，不声称已独立证实。
