# 多机械臂任务的端点表达与时序协调

状态：讨论中的想法与问题，尚未形成生成器需求或实现方案。

## 背景与原始想法

学习 MotionBenchMaker 的 start/goal query 表达时，我开始考虑：单机械臂的连续操作可以拆成一段段运动规划问题，但多机械臂的执行进度不一定一致，各臂可能运动、等待或处于不同任务阶段。因此，需要讨论“每臂一对 start/goal”能够表达什么，以及它可能忽略什么。

我的研究中，“时序”是一种协调手段：通过安排机械臂何时运动、等待和让出空间，解决共享工作空间中的冲突。

我最初将“每臂一对 start/goal”理解为各臂同时开始执行各自的运动任务，允许途中等待，也允许提前到达，但当时没有考虑错开开始执行的情况。我也联想到，更异步的多机械臂任务可能与任务与运动规划（TAMP）有关。

## 理解变化：端点描述与执行时序

经讨论，进一步区分了端点描述与执行时序：start/goal 本身不要求各臂同时出发，也可以允许错开执行。这是讨论中对原始理解的扩展，不应倒写为我最初就有的认识。

agent 进一步指出，“同时开始执行任务”与“同时开始实际运动”也需要区分。如果允许机械臂在起点等待，那么即使任务统一开始，各臂仍可能错开实际运动。

因此，“每臂一对 start/goal”是否构成了不合适的简化，不能仅根据是否同时运动判断，还需要检查它如何表达任务过程和完成条件。

## 新问题：到达之后发生什么

agent 提出，应区分整个任务完成后的终止状态，与完成局部操作后仍需撤离或继续运动的中间状态。这一点是我此前没有注意到、认为值得保留的问题。

“最终目标”表示当前所建模任务的完成状态，但它本身不规定完成后的行为。

如果显式采用“完成后停留”的约定，机械臂到达最终目标后不再运动，并持续占据相应空间。这是需要明确选择的建模约定，不能仅凭 start/goal 描述就默认采用。

因此，除了“何时到达”，还应讨论目标是最终状态还是中间状态，以及完成后机械臂如何运动或占据空间。

明确这一问题非常重要，因为任务过程、完成条件以及完成后的行为约定，共同界定了研究范围。它们决定哪些协调情形被纳入研究、哪些被排除，以及实验结果能够支持多大范围的结论。

如果没有明确这些约定，就可能在不自觉的情况下对研究问题作出不恰当的简化。简化应当明确说明，并检查它是否保留了研究所关注的时序协调问题。

## 例子一：共享加工区域中的访问与撤离

以下是 agent 构造的例子，不是 MotionBenchMaker 的原始实验：

双臂 A、B 都要进入同一个狭小加工区域，完成操作后撤回。

- 若将两臂的加工姿态都设为最终目标，并显式采用“完成后停留”的约定，则最终目标组合可能发生碰撞。
- 若加工姿态只是中间状态，任务表达为各臂分别“进入—操作—撤出”，则可能通过错开占用时间完成。
- 两种表达的区别不仅在于运动时间，还在于任务完成条件，以及是否保留操作后的撤离过程。

这里的“可能完成”依赖具体几何条件和可行路径，不是对所有此类场景的保证。

将“访问加工位置后撤离”压缩为“到达加工位置”，会丢失撤离过程；再额外采用“完成后停留”的约定，还可能改变原问题的可解性。

## 例子二：未经澄清的理解可能缩窄 planner 的能力范围

我提出一个担忧：如果依据最初“各臂同时开始、允许途中等待和提前到达，但没有考虑错开开始”的理解设计 planner，最终能力范围可能很窄，甚至不如原版 Stop-N-Go。

agent 判断，这适合作为风险提醒，但不能仅由“同时开始”推出上述结论：如果允许在起点等待，错开实际运动仍可能被表达。

更准确的风险是：若将这一初始理解落实为“每臂只有一次 start→goal 运动”，并因此省略访问序列、操作后的撤离及跨阶段协调，最终 planner 的问题覆盖范围就可能比原版 Stop-N-Go 更窄。

对照依据是 Stop-N-Go 论文 §III：每个机器人被分配一个目标序列，并假设完成序列后返回初始位置。其 §IV-A 则以已有轨迹为输入，通过插入暂停进行协调。

例如，对“进入加工区域—完成操作—撤回”这一过程，如果我们的模型只保留到加工位置的一段，就无法完整提出和评估撤离过程中的协调问题。

这里比较的是任务表达与问题覆盖范围，不是已经验证的算法性能差异。当前生成器和新 planner 均未据此确定方案，不能记录为已有实现的缺陷。

## 暂时理解

每臂一对 start/goal 可以用于研究时序协调，但单一端点对可能不足以保留访问、操作和撤离的任务过程。

agent 补充：增加已给定的访问序列，不意味着必须立即研究完整 TAMP。可以先区分“任务序列已给定，研究运动与时序协调”和“任务动作及其安排也需要规划”这两类问题。

以上是当前讨论中的理解，不是已经确定的研究范围。

## 未决问题

- 一个问题样本应表达共同终态，还是各臂需要完成的访问过程？
- 每个目标位置是最终状态，还是需要访问后离开的中间任务位置？
- 任务完成后的运动与空间占用，应采用什么显式约定？
- 哪些时序应由问题给定，哪些应留给协调算法决定？
- 采用的简化是否保留了我们希望研究和评估的协调情形？由此得到的结论适用于什么范围？

agent 另提出一个待讨论的问题：将连续任务拆成多段时，是否额外引入了“所有机械臂完成当前段后才进入下一段”的同步要求？这一点尚未展开，也不是用户已经确认的主张。

这些问题是对未来生成器的启发，不是已确认的功能需求或技术方案。
