## 独立核查与差异

所有组副本与结束时原件逐字节一致，且 SHA-256 与开工快照一致，索引本地文件路径均有效。逐组检查来自实际文件和原文，未仅依据子 agent 自述。原文内部指向未收附件或业务资料的链接保持原样；这与 INDEX 自身路径失效分开判断。

- **sol_high**：漏收研究仓库 09-16 的纠正案例：用户要求标记“尚未确定”，agent 却补齐方案。已收文件未见确定误收。

- **sol_xhigh**：覆盖核查集；额外收录 6 行 todo 草稿和预览工具说明。均有具体理由且状态明确，属于相关性边界较宽的收录，不能硬判误收。

- **sol_max**：覆盖核查集，技术背景扩张明显，额外纳入全部 7 份公开 API 契约。作为实际交接物有依据，但对规则素材汇集是否需要全量留存存在争议；不因文件多就评为更优。

- **astra_high**：覆盖核查集；结果是 sol_xhigh 的子集，仅少 todo 草稿和预览工具说明。逐份解释 Markdown 排除理由，选材边界清楚。

- **astra_xhigh**：用 50 份文件覆盖核查集，与同样收 50 份的 sol_high 内容不同；保留 StAC 笔记的证据标注案例，省去若干状态和项目入口背景。采用逐文件段落索引与概括性行号范围。

- **astra_max**：49 份文件覆盖核查集，背景收录最少；保留旧设计入口，排除 StAC 笔记和基准验证说明。边界较窄有助聚焦，但不能据此宣称穷尽协作经验或稳定优于其他组。

各组对确认、候选、探索执行和历史结果均作区分。更细的状态标注、章节定位及范围审阅见 [reviewer-findings.json](audit/reviewer-findings.json) 和 [product-verification.json](audit/product-verification.json)。
